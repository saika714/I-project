## 0. AIへの最優先指示

あなたはUnity 6 / C#のシニアゲームエンジニア兼テクニカルディレクターである。既存プロジェクトを監査した後、**PC上で最初から最後まで遊べる初心者向けソフトボールゲーム**を段階的に実装すること。VR対応は後続フェーズとするが、入力・視点・バット姿勢の抽象化は初期段階で行う。

- 最初に `Assets/`, `Packages/`, `ProjectSettings/` を調査し、Unityの実際のバージョン、URP、Input System、既存シーン、ライセンス不明の素材、既存スクリプトを確認する。共有された概要は現状の保証ではない。
- 既存ファイルを一括削除しない。既存 `SampleScene` はバックアップし、新規のゲーム用シーンとコードを分離する。
- 実装可能な小さな縦切りスライスから進める。最初の目標は「タイトル→投球→スイング→打球→結果→次の投球」。
- 見た目の仮素材を許容するが、操作の気持ちよさ、打球の見やすさ、初心者の成功体験を優先する。
- 外部アセット・SDK・有料素材の導入は勝手に行わない。差し替えポイントを先に設ける。
- Unityの実APIを確認せずに存在しないクラス・パッケージAPIを仮定しない。コンパイルエラーを残さない。
- 各フェーズ終了時に変更ファイル、起動手順、テスト結果、残課題を報告する。作業途中でもゲームが起動できる状態を維持する。

## 1. 背景・解決する課題

本プロジェクトは、研究室の留学生・日本人学生の交流機会を増やし、ソフトボール大会に未経験者が関わる入口を作るためのVR体験を開発するもの。経験豊富な先輩の卒業に伴う参加者の世代交代も背景にある。言語や競技経験によらず「打てた」「どの塁へ進むか分かった」「一緒に盛り上がった」と感じられる設計とする。

**達成したい体験価値**
1. 説明をほとんど読まずに投球・打撃を理解できる。
2. 初心者でも数球以内に成功体験を得やすい（達成率はテストで検証し調整）。
3. 打撃後の走塁・得点の因果関係が目で分かる。
4. 画面を見ている友人も声をかけやすく、結果を一緒に喜べる。
5. 日本語・英語を切り替えられ、文字に頼らない誘導を備える。

**対象**: 野球・ソフトボール未経験の学生、留学生、VR初心者。ワークショップでは1人のプレイを周囲が見守る形式。ゲーム単体で交流が自動的に発生するとは断定せず、進行・会話の仕掛けも設計する。

- `Floreswa`: 仕様と画風・ライセンス・リグ互換性を調査し、使えなければ差し替える。
- `InputSystem_Actions.inputactions`: 内容を監査し、専用Action Mapへ整理。
- `Settings`: URP設定を活用し、PC向け品質と将来のQuest向け軽量品質を分離。

## 3. ゲームの世界観・アートディレクション

仮タイトル: **Softball Connect**。実在するゲームのキャラクターやロゴを複製しない。パワプロのような「頭が大きく、短い手足、表情が豊かな」親しみやすさを参考にしつつ、独自の丸みあるデフォルメ3Dキャラクターを作る。

- キャラクター: 2.5〜3頭身程度を目安。選手は打者、投手、捕手、内野手、外野手。最初は色違いの共通Prefabでよい。
- 球場: **明治神宮野球場をモチーフ**に、青い観客席、緑の芝、内野土、外野フェンス、大型スコアボード、照明塔をスタイライズドに表現。実球場の寸法・ロゴ・看板を厳密に複製しない。
- **競技フィールドはソフトボール基準**とする。球場の外観と、塁間・投球距離・下手投げなどの競技仕様は別物として設計する。寸法は年齢・大会ルールに応じて設定アセットから変更可能にし、研究室大会のルールが判明したら反映する。
- 視覚設計: 球・バット・塁・守備位置が背景に埋もれない。投球予告、打撃タイミング、打球軌跡、走塁選択を色・形・動きで伝える。
- 仮アセット: Primitive/Meshを使ったキャラクターと球場でも成立させる。モデル・アニメーション・音・UIはPrefab/ScriptableObject経由で差し替える。
- 演出: ヒット時の短いヒットストップ、打球トレイル、カメラ追従、観客歓声、結果表示。VRでは激しいカメラ移動やヒットストップによる視点停止を適用しない。

## 4. ゲームモード・優先順位

### M0: 打撃の縦切りスライス（最優先）
タイトル→バッターボックス→投球→PCスイング→衝突/空振り→打球飛翔→結果→再挑戦。最初は守備・走塁なしでもよい。

### M1: バッティング練習
球速やコースを段階的に変える。打撃タイミングのフィードバック（早い/ちょうど/遅い）、当たりの強さ、飛距離の目安、連続ヒット表示。初心者向けアシストは明示的にON/OFF可能。

### M2: 走塁チャレンジ
打撃後に打球・守備の様子を見て「進む」「止まる」を選ぶ。走者は自動移動し、判断と結果を短く説明。最初は1塁から2塁を狙う代表的な場面に限定してよい。セーフ/アウトは守備の送球・走者到達を用いた簡略判定とし、単なるランダム結果にしない。

### M3: ミニゲーム（ワークショップ用）
3〜5分程度の短いラウンド。例: 5球の打撃と1〜2回の走塁判断、最後にスコア・振り返り・次のプレイヤーへの交代案内。スコアは競技経験の少ない人にも理解できるものにする。観客用画面に状況を大きく表示。

### M4: VRモード（後続）
Meta Quest + コントローラーを仮想バットの姿勢に反映。実物バットへの取り付けを想定するが、**安全性が検証されるまでは実バットを使用しない**。取り付け固定、周辺空間、HMDとの衝突、第三者との距離を検証し、必要なら軽量フォームバットや専用グリップに変更する。

## 5. ゲームループ・画面遷移

`Boot → MainMenu → ModeSelect → Tutorial → Gameplay → Result → Replay/ModeSelect`

Gameplayの状態:
`Prepare → PitchWindup → BallInFlight → SwingWindow → Contact/Miss → BallInPlay → (RunDecision) → PlayResolved → Feedback → Prepare`

- 状態遷移は一元管理し、複数スクリプトが独自に投球開始・得点確定しない。
- ポーズ、リトライ、言語切替、音量、難易度を用意。
- 初回チュートリアルは「見る→打つ→結果を見る」を短く分ける。走塁の説明は走塁モード開始時に行う。
- 走塁は自動移動と判断入力が中心。VRでプレイヤー自身を走らせない。
- ワークショップでは外部モニターの観客用表示を想定し、プレイヤーUIと観客UIを分離可能にする。

## 6. PC操作と将来のQuest操作

| 行動 | PC初期実装 | Quest将来実装 |
|---|---|---|
| 視点 | 固定の打者視点 + マウスで軽く調整（任意） | HMD追従 |
| バット位置・向き | 初期は固定の打撃平面とマウスによる狙い調整 | コントローラーの6DoF姿勢 |
| スイング | Space/左クリックでタイミング入力。アニメーション駆動のバット軌道 | 物理的なスイング速度・姿勢 |
| 走塁選択 | 左右キー/ボタン、Enter確定 | コントローラーボタン/ポインタ |
| メニュー | マウス/キーボード | VR UIポインタ |
| リセット | R | メニュー操作 |

**重要**: PCのSpace入力は「スイング意図」を発火し、内部の `BatPose` / `SwingSample` へ変換する。Questはトラッキングした姿勢・速度を同じ形式へ変換する。ゲームルールや打撃結果判定は入力デバイスを直接参照しない。

推奨インターフェース（実装の命名は調整可）:
```csharp
public interface IBatInputSource
{
    BatInputFrame Sample(float deltaTime);
}

public readonly struct BatInputFrame
{
    public readonly Pose BatPose;
    public readonly Vector3 LinearVelocity;
    public readonly Vector3 AngularVelocity;
    public readonly bool SwingTriggered;
    // コンストラクタ等は実装時に追加
}
```
PCは `DesktopBatInputSource`、VRは `XRBatInputSource`、テストは `ScriptedBatInputSource`。`IBatInputSource` をMonoBehaviourのInspectorへ直接シリアライズしようとせず、アダプタ/プロバイダで解決する。

## 7. 打撃・投球・打球の仕様

### 7.1 投球
- 投手はソフトボールの下手投げを基本とし、まずはアニメーション/手続き的モーションで再現。
- 球種は初期段階では直球のみ。球速・到達時間・コースばらつきは `PitchConfig` で設定。
- 投球はリリース位置・目標位置・飛行時間から再現可能な軌道を生成する。見た目と当たり判定の位置が一致すること。
- 初心者向けには予告動作と投球間隔を十分に設ける。

### 7.2 スイングと衝突
- バットの見た目と判定を分離。判定はバットの有効区間を表すカプセル/線分の**前フレーム→現フレームの掃引**と、ボール軌道の時間区間との近接判定を用いる。高速移動時のすり抜けを防ぐ。
- PCではアニメーション駆動のバット軌道をサンプリングし、VRでは実測姿勢をサンプリング。衝突処理の共通化を優先。
- 接触結果は `ContactPoint`, `ContactNormal`, `RelativeVelocity`, `TimingOffset`, `SweetSpotOffset` などから計算。
- 「当たったのに空振り」「球が離れているのにヒット」を避ける。アシストを使う場合は判定幅を設定値で拡張し、無制限な自動命中にはしない。
- 初期は物理的厳密性より**一貫した予測可能性と操作感**を優先。デバッグ表示でバット軌跡・球軌跡・衝突位置を確認できるようにする。

### 7.3 打球
- 接触時に打球初速度・方向・打ち上げ角を求める。タイミング、スイング速度、芯からのずれを反映。
- 飛行中は重力・必要に応じて簡略空気抵抗を適用。初期は地面・フェンスとの衝突と停止を実装。
- PCでも打者の目位置を維持し、打球の行き先は方向表示と手動の視線調整で追う。VRでは頭の追跡姿勢を反映し、プレイヤー原点を強制移動しない。
- フェア/ファウル、ゴロ/フライ、飛距離、着地点の簡易分類を返す。

### 7.4 守備・走塁
- 最初は守備位置に応じた簡易AIでよい。`fielder → target ball → pickup → throw` の状態を持たせる。
- 走者は塁間パスを移動し、進む/止まる入力を受ける。打撃後の代表場面を優先し、複雑な野球ルールの全面実装は後回し。
- ルールは `SoftballRuleConfig` に分離。研究室大会固有のルールは未確認のため、後で変更できるようにする。

## 8. ソフトウェアアーキテクチャ

**原則**: Unity依存の薄いPresentation層と、可能な限り純粋C#のDomain層を分離。イベント駆動を使うが、イベント乱立を避ける。1つの `GameSessionController` が進行状態を管理する。

```text
[Input Adapters]
 Desktop Input / XR Input / Scripted Test Input
          |
          v
[Application / Orchestration]
 GameSessionController -- TutorialFlow -- ModeController
          |
          v
[Domain / Simulation]
 PitchModel -- BatContactSolver -- BallFlightModel
 RunDecisionRules -- ScoreRules -- GameState
          |
          v
[Presentation Adapters]
 Player/Bat/Ball Views -- Stadium -- Cameras -- UI -- Audio/VFX
          ^
          |
[Config / Content]
 ScriptableObjects: difficulty, field, pitch, bat, rules, visuals
```

責務:
- **Domain**: 状態、判定、スコア、軌道の計算。`MonoBehaviour`やシーン参照を極力持たない。
- **Application**: 入力の受け取り、状態遷移、モードごとの進行、イベント発行。
- **Infrastructure**: Input System、XR SDK、設定ロード、ログ、セーブ。
- **Presentation**: Unity GameObject、Animator、Camera、UI、VFX、Audio、球場。
- **Content**: ScriptableObject設定とPrefabの参照。

主なコンポーネント候補:
`GameBootstrap`, `GameSessionController`, `GameStateMachine`, `PitchService`, `BatSwingController`, `BatContactSolver`, `BallFlightSimulator`, `RunDecisionController`, `FielderController`, `ScoreService`, `TutorialDirector`, `FeedbackPresenter`, `CameraDirector`, `LocalizationService`, `GameConfig`。

イベント例: `PitchStarted`, `BallReleased`, `SwingStarted`, `BallContacted`, `SwingMissed`, `BallLanded`, `RunDecisionRequested`, `RunnerAdvanced`, `RunScored`, `PlayResolved`。イベントには必要な値を持たせ、購読解除を徹底する。重複発火を防ぐ。

## 10. アセット差し替え設計

- キャラクターは `CharacterView` の下にモデル表示用の子オブジェクトを持たせ、ルートのゲームロジック・Collider・位置制御を固定。モデルだけPrefab差し替え可能。
- アニメーションは意味ベースの状態（Idle, Ready, Pitch, Swing, Run, Catch, Celebrate）で制御。仮アニメーションでも同じ契約を使う。
- 球場は `StadiumRoot` 以下を `FieldGeometry`（判定用）と `StadiumVisuals`（見た目）に分離。見た目を交換しても塁位置や打球判定が変わらない。
- バットは `BatRig`（姿勢/判定）と `BatVisual`（モデル）を分離。グリップ位置、長さ、半径、コントローラーとのオフセットを設定化。
- UIはゲーム状態からViewModel的な表示データを受け取り、ゲームルールを直接書かない。
- 効果音・歓声・音楽はイベントに応じた `AudioCue` に割り当てる。

## 11. UI/UX・言語・観客との交流

- 初期表示は英語、日本語への切り替えを用意。TextMeshPro等の既存利用状況を確認して採用。テキストをコードに直書きしない。
- チュートリアルは3段階程度の短いカード、アイコン、ゴーストスイング、矢印で構成。
- 打撃時は「球を見る」「今！」などの補助を難易度に応じて表示。
- 結果画面: ヒット種別、飛距離目安、タイミング評価、得点、次のアクションを大きく表示。
- 走塁: 塁の方向と選択結果をアニメーションで説明。失敗時は責めずに理由を示す。
- 観客用: 現在のプレイヤー、残り球数、結果、次の挑戦が見える。体験者に「どちらの塁を狙う？」と声をかけられる仕掛けを検討。
- 得点演出では慶應の応援文化を紹介する短い表示を用意。**「若き血」の音源は権利・利用許諾を確認するまで組み込まず、差し替え可能な仮のオリジナルジングルを使う。**
- 光や音に頼りすぎず、字幕・形状・アニメーションでも情報を伝える。

## 12. カメラ・パフォーマンス

- PC: 打者の目位置を基本とし、右ドラッグで視線を調整。打球後も結果時もプレイヤー原点を固定し、追従・俯瞰カメラへ自動遷移しない。
- VR: XR Origin基準でプレイヤー位置を固定。打球追跡はミニマップ/視線誘導等を利用し、HMDカメラを自動移動させない。
- URPのPC品質とQuest品質を分離。VRでは軽量シェーダ、LOD、ベイクドライト、適切なドローコール削減を想定。
- フレームレート・GC割当・物理ステップをプロファイルする。Quest性能は実機で検証するまで保証しない。

## 13. データ・設定・計測

ScriptableObject候補:
- `GameModeConfig`: 球数、走塁回数、制限時間、結果条件。
- `DifficultyConfig`: 球速、投球間隔、当たり判定アシスト、ガイド量。
- `PitchConfig`: 投球軌道・コース分布。
- `BatConfig`: 長さ、スイートスポット、入力感度、VRオフセット。
- `FieldConfig`: ホーム・塁・フェンス・投手位置など。
- `SoftballRuleConfig`: セーフ/アウト、得点、走塁ルール。
- `VisualThemeConfig`: 球場配色、キャラクター、VFX参照。

ローカル計測（個人情報を記録しない）:
- プレイ時間、投球数、スイング数、接触数、空振り数、打球分類、走塁選択、正誤/結果、チュートリアル再表示、言語、難易度。
- ワークショップの前後アンケートとは区別し、収集する場合は参加者に説明する。
- 体験評価: 楽しさ、達成感、ルール理解、競技への関心、交流のきっかけ。数値目標は試行テスト後に設定する。

## 14. テスト・受入条件

**EditMode**
- 同一条件の投球軌道が再現される。
- 打球のフェア/ファウル分類、スイング時間窓、接触計算、得点・アウト判定の境界値を検証。
- GameStateの不正遷移を拒否する。

**PlayMode**
- メニューから開始→5球プレイ→結果→リトライが例外なしで完走。
- 連続スイングで重複判定しない。
- リスタート後に球・走者・UI・カメラが初期化される。
- 日本語/英語切替後にレイアウトが崩れない。
- 仮モデルを別Prefabに差し替えてもプレイ可能。
- PC操作にQuest SDKが必須にならない。

**体験品質**
- 初見ユーザーがスタッフの長い説明なしで最初の投球に進める。
- ヒット/ミスの理由が視覚的に伝わる。
- 打撃と走塁と得点の関係を振り返れる。
- 観客がプレイの状況を把握できる。
- VR実装時は安全確認と酔い対策を別途受入条件とする。
